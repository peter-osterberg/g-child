# Accessibility Guidelines

- Treat WCAG 2.2 AA as the default accessibility target unless the repository, client, or legal requirement sets a different standard.
- Prefer semantic HTML and native controls before custom widgets or ARIA.
- Use links for navigation and buttons for actions.
- Preserve keyboard access, logical focus order, and visible focus indicators for all interactive UI.
- Provide programmatic names, labels, descriptions, errors, states, and relationships for controls and dynamic content.
- Do not hide meaningful content from assistive technology unless an equivalent accessible path exists.
- Do not expose decorative content to assistive technology.
- Keep heading hierarchy, landmarks, and page structure meaningful within the surrounding context.
- Respect reduced-motion preferences for animations, transitions, scrolling effects, and scripted movement.
- When accessibility cannot be verified automatically, call out the manual keyboard, screen reader, viewport, or zoom checks that remain.
