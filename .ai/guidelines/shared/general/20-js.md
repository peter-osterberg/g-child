# JavaScript Guidelines

- Use `const` and `let`, never `var`.
- Use strict equality: `===` and `!==`.
- Always use curly braces for control structures, even single-line branches.
- Write control-flow bodies on separate lines. Do not compress `if`/`else` or `try`/`catch` blocks into one-line statements.
- Keep functions small and intention-revealing.
- Extract a named helper when inline logic becomes hard to read. In class-based modules, keep helpers on the owning class: use instance methods for behavior that depends on instance state and static methods for helpers independent of instance state.
- In class-based modules, reserve standalone named functions for bootstrapping or initializing the class. Inline callbacks and framework-defined component methods can remain in their normal locations.
- Add JSDoc only for shared or non-obvious functions.
- Prefer semantic HTML and CSS before adding JavaScript.
- Build frontend behavior as progressive enhancement with small, focused modules.
- In WordPress projects, do not hard-code user-facing English strings in JavaScript; pass translated strings and settings from PHP with `wp_localize_script()` or the repository's established script-data helper.
- Keep UI state local when possible and reflect state with native DOM state, classes, or attributes.
- Use stable selectors or established component hooks instead of fragile DOM-depth assumptions.
- Preserve keyboard support, focus behavior, accessibility state, and reduced-motion expectations for interactive UI.
- Avoid heavy libraries, global state systems, and framework-like patterns for small interactions.
